# 코드 복사 (공용화 대신)

> 전제: `AGENTS.md` §1.2. **복사가 이 프로젝트의 기본값이고, 승격(공용화)은 금지다.**

## 먼저 판단할 것

사용자가 "공통으로 빼줘", "중복 정리해줘" 라고 요청했더라도, **대상이 무엇인지에 따라 답이 다르다.**

| 대상 | 처리 |
| ---- | ---- |
| UI 컴포넌트, 화면 조각, 표시용 포맷 함수 | **복사한다.** 공용화하지 않는다 |
| 색상·간격 값 | 이미 `@/styles/tokens.css`에 있다. 복사도 신설도 하지 않고 **토큰을 쓴다** |
| http 호출·인증·토큰 처리 | `@/lib/`에 이미 있거나, 거기 추가한다. **복사 금지** |
| 서버 응답 타입 | `@/types/`에 둔다. **복사 금지** |
| 가격 계산·유효성 규칙·권한 판정 | 답이 하나여야 하므로 `@/lib/`에 둔다. **복사 금지** |

기준은 **"틀렸을 때 누가 알아채는가"** 다. 버튼 모서리가 두 화면에서 갈라져도 아무 일도 없지만,
할인율이 갈라지면 돈이 틀리는데 화면은 멀쩡하다.

**사용자가 명시적으로 공용화를 지시했고 대상이 UI라면** — 지시를 따르되, 실행 전에
영향받는 파일 전부와 §1.2 정책을 함께 보고하고 확인을 받는다. 조용히 진행하지 않는다.

## 복사 절차

### 1. 원본 확인

```bash
grep -rn "@duplicate-of" src   # 이미 복사본이 있는지 먼저 본다
```

이미 같은 원본에서 나온 복사본이 있다면, 그중 **가장 가까운 것**을 복사한다(원본이 아니라).
그쪽에 이미 필요한 수정이 들어가 있을 수 있다.

### 2. 대상 위치로 복사

```
src/features/<대상기능>/components/<이름>.tsx
```

### 3. 출처 주석 남기기 (필수)

복사본 맨 위, import보다 위에 둔다.

```tsx
// @duplicate-of: src/features/greeting/components/GreetingCard.tsx
import type { Movie } from '../types'
```

이 한 줄이 하는 일:

1. 원본에서 버그를 고칠 때 `grep -r "@duplicate-of" src` 로 형제 복사본을 전부 찾을 수 있다
2. 기술부채 정리 기간에 후보 목록이 이미 만들어져 있다

**중복의 유일한 실제 비용은 "버그 수정이 복사본에 전파되지 않는 것"이고, 이 주석이 그것을 막는다.**
주석 없는 복사는 미완료로 간주한다.

### 4. 대상 feature에 맞게 고치기

복사본은 **원본과 달라져도 된다.** 오히려 그게 정상이다.

- 타입 import 경로를 대상 feature의 `../types`로 바꾼다
- 필요 없는 props는 지운다
- 대상 기능에 맞게 이름을 바꾼다 (`GreetingCard` → `MovieCard`)

원본과 똑같이 유지하려고 애쓰지 않는다. 복사한 순간부터 둘은 별개다.

### 5. 검증

```bash
npm run lint && npm run build
```

## 버그를 고칠 때

복사본이 있는 코드에서 버그를 고쳤다면, 형제 복사본도 확인한다.

```bash
grep -rn "@duplicate-of: src/features/greeting/components/GreetingCard.tsx" src
```

**같은 버그가 있는지 확인만 하고, 고칠지는 사용자에게 묻는다.** 형제 복사본은 이미 각자 다르게 바뀌어 있을 수 있어서,
같은 패치가 그대로 맞지 않을 수 있다.

## 하지 말 것

- ❌ 복사 대신 import (`@/features/other/...` — 린트 에러)
- ❌ `@duplicate-of` 주석 생략
- ❌ 복사본 3개가 생겼다고 자발적으로 합치기
- ❌ 공용 폴더(`src/components/` 등) 신설
- ❌ "원본을 수정해서 양쪽 다 되게" — 그게 바로 이 프로젝트가 막으려는 사고다
